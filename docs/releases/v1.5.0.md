# Agentic Security Harness v1.5.0

This document describes the additive v1.5.0 release source. It alone is not evidence of
a GitHub Release, TestPyPI/PyPI publication, deployment, or production enforcement.
Publication requires exact tag-bound build, provenance, index and installation evidence.

## Highlights

- The opt-in [Quarantine Connector](../quarantine-connector.md) decodes a closed canonical
  model envelope under an explicitly selected profile and returns a typed admission
  verdict. Its separate composition stops at the existing pure Gateway policy decision.
- The [advisory-to-Gateway connector](../advisory-gateway-connector.md) binds advisory
  results to caller-owned capabilities and immutable replay transitions. Neither advice
  nor model output can create an action grant.
- Strict source-result ingress and external Playbooks synthetic receipt-pair validation
  bind exact input/output identities, subjects, pack/rule pins and semantic accounting.
  Malformed JSON types and Unicode are typed refusals before downstream evaluation.
- These are explicit Python APIs, not a new CLI, listener, provider transport, automatic
  companion loader, durable audit writer or dispatcher. Core Gateway policy remains the
  action decision boundary; the new compositions do not execute actions.

## Compatibility

Trace 1.0 and corpus 1.0.0 remain unchanged. The passive `transfer`, `handoff`, `playbooks`,
`router`, `filter` and `all` extras retain the exact versions listed in
[v1.4.0](v1.4.0.md). Companion source repairs are not implicitly included in those old
distributions. Installing an extra does not activate it or confer authority.

Install the published exact version:

```bash
python -m pip install agentic-security-harness==1.5.0
ash quickstart --out reports/quickstart
ash agent-host-quickstart --out reports/agent-host-quickstart
```

Both quickstarts use built-in public synthetic fixtures with no provider calls. Python
3.11-3.13 on Linux and Python 3.11 on Windows are the tested package contours.

## Verification and limits

The release gates cover complete pytest, Ruff, mypy, committed-artifact validation,
reproducible wheel/sdist builds, installed-package smokes, SBOM/checksums and exact-source
attestations. The same attested wheel/sdist must pass TestPyPI before PyPI promotion;
post-publication verification checks index hashes and clean Linux/Windows installation.

Synthetic conformance is not a production safety certification. Byte/digest checks do
not authenticate a receipt producer or establish model intent. No new live-provider,
real-target, arbitrary-tool, credential, production deployment or enforcement capability
is claimed. Independent standards review and second-maintainer governance remain open.

See [CHANGELOG](../../CHANGELOG.md), [release checklist](../release-checklist.md) and
[publication procedure](../release-to-pypi.md).
