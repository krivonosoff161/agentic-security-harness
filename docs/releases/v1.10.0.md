## Scope

This minor candidate adds the public `ControlledFileSession` hook to the opt-in [controlled file workflow](../controlled-file-workflow.md). A trusted application creates a fresh synthetic fixture, chooses context and capture labels, and submits bounded proposal bytes. Quarantine, retained ancestry and report-only Guard precede a retained-handle file write. The model cannot choose paths, labels, authority or executable code through the hook. The session limits attempts and cannot resume after closure or a persistence/effect failure.

The candidate also returns a content-free nonzero diagnostic on ancestry storage or integrity failure and retains incomplete evidence. An affected proposal does not reach Guard or a write after that failure; earlier completed writes may remain. The caller must inspect result records and file bytes rather than infer rollback. Installed `doctor` and focused fault coverage exercise this boundary.

An optional [Pydantic AI example](../../examples/pydantic_ai_guarded_files.py) inserts the hook inside an actual tool callback. Its fixed FunctionModel controls make no provider calls. Pydantic AI is separately pinned for verification and is not a base Harness dependency or endorsed upstream integration. The [eight-case public seed](../../examples/boundary-seed-v1.json) includes four development and four known reserved cases with independently declared expected outcomes. The exporter verifies a completed local capture read-only before creating a new seed file; the dataset is neither blind evaluation nor trained classifier evidence.

## Bounded local evidence

Six unmodified local Qwen2.5 1.5B replies through the external Agent loop and public session hook led to four report writes, two correct reports and two protected-write denials. Two fixed controls were separate; all eight protected files remained unchanged. The model series used six native loopback requests and twelve framework requests, with no retry or response repair. Read-only ancestry/effect checks and five in-memory tamper rejections are distinct from model correctness.

A prior offline ten-repetition integration run retained 80 tool calls, 160 scripted framework requests, zero provider calls, 20 report writes, 10 protected denials and 50 shape rejections. A separate 30-row audited timing decomposition retained ten writes, ten Guard denials and ten shape denials with all 30 protected files unchanged. On that Windows machine, whole-submission median for the permitted report path was 650.73 ms; storage/history and attempt receipts dominated measured cost. These runs are distinct from the six model observations, and the first-stage hook timings predate the public session's additional receipts. No production latency or cross-model reliability estimate follows.
