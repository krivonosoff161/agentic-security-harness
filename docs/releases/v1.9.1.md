# Agentic Security Harness v1.9.1

Status: prepared documentation/packaging patch; not yet published.
The current verified package remains [1.9.0](v1.9.0.md).

## Reason for the patch

PyPI 1.9.0 has the correct 1.9.0 wheel and sdist, but its description was copied
from the repository README before final publication. That snapshot calls the
workflow a candidate and recommends 1.8.0. Updating GitHub's README did not change
the package-index description. This is a presentation defect, not absent binaries
or failed delivery of the controlled file workflow.

The [PyPI JSON API contract](https://docs.pypi.org/api/json/#get-a-project) states
that the first uploaded release metadata is stored; subsequent uploads do not
update it. Do not delete, replace or re-upload 1.9.0 to change that description.

## Change

`pyproject.toml` uses the dedicated `PACKAGE_README.md`, describing this exact
distribution rather than claiming a current promotion status. CI and the tag
workflow inspect the actual wheel `METADATA` and sdist `PKG-INFO` before upload.
Their version, Markdown content type and description must match the reviewed
source. The sdist must also retain the exact package-description source.
The check reads archives without extracting or executing package code.

Runtime behavior, authority, dependency pins and companion versions are unchanged.
The package version leaf changes to 1.9.1. No model campaign is repeated and no
historical observation is relabelled as a 1.9.1 measurement.

## Publication gates

Before calling this patch published, record the exact reviewed source, successful
CI, attested tag subjects, TestPyPI verification, separately authorized PyPI
promotion and read-only final verification. Also compare the official index
description with the attested distribution metadata. A green GitHub README check
alone is insufficient.

No release hashes or run identifiers are claimed before those operations complete.
Keep the [1.9.0 receipt](v1.9.0.md), including initial failed observations, intact.
