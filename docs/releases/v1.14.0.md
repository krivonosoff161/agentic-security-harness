Status: **merged source, not published**. [PR #354](https://github.com/krivonosoff161/agentic-security-harness/pull/354)
merged at `c36679812acf1a64a7095f59b06ce388695813e9`. The published package

page is a release plan and source-evidence summary, not a publication receipt.

## Scope

- Align the optional Pydantic AI 1.x integration at 1.107.7 with coherent
  Linux/Windows hash-locked verification sets and dependency-consistency tests.
  This does not migrate to optional Pydantic AI 2.x.
- Require exact-byte host acknowledgment before reusing a checklist-matched
  document, including older `checked` records. Failed exact JSON requirements
  remain ineligible; literal checklist terms alone never establish meaning.
- Compose host-retained coverage expectations, ancestry checkpoint, captured
  observations, channels and manifest digest as observational telemetry. A
  pending host phase remains pending even when records are present. Telemetry
  does not grant execution authority.
- Retain consumed grants for a bound create-only workspace operation. Supported
  old deliveries are fenced after verified absence; exact bytes after an
  interrupted write can reconcile the file **postcondition**, not prove that
  the prior call returned. Partial or different bytes remain unknown and are
  not overwritten.
- Provide a host-owned source-capture assembly and two-step installed example
  joining four source kinds, original restrictions, admission and a guarded
  write. A bad-quality first draft cannot become the second task's source.
  The optional planner chooses only a closed query; the host computes it from
  trusted task data, and a valid but wrong query remains a task failure.

## Source verification and evidence limits

At the reviewed pre-merge source snapshot, all 35 PR checks passed. Its six
Windows/Linux reports covered 3,245 passing nodes across 173 modules; platform
skips and earlier failed attempts remain separate. A subsequent bounded
installed-candidate acceptance ran 150 targeted tests and 47 scripted checks.
These are source/candidate observations, **not** evidence that a 1.14.0 tagged
wheel, TestPyPI subject or PyPI subject has passed its own gates. See the
[acceptance map](../project-tracker.md#research-closure-candidate--pr-354) for
the distinction between mechanisms, task results and assumptions.

The source-reading studies retained incorrect model outputs; exact-byte
transfer is a separate route for already selected bytes, not a semantic
classifier. A matching review digest binds bytes but does not establish that
a person reviewed them or that their claims are true. No universal free-text
faithfulness, arbitrary-tool exactly-once recovery, hostile-host rollback
resistance, complete capture of uninstrumented events, production deployment,
or independent human review is claimed. Issues #316, #317, #343 and #353 are
not declared closed by this merged source or this candidate note.

## Remaining delivery gates

The release branch must pass its exact-head CI and source/package identity
checks. The canonical `v1.14.0` tag must match package metadata, changelog,
citation, release notes and built subjects. TestPyPI staging, separate owner
approval for production, PyPI promotion and read-only cross-index verification
remain future evidence. Record initial failures rather than replacing them with
an unlabelled retry. Only then reconcile the related issue and advisory states.
