# Agentic Security Harness v1.9.0 — controlled file effects

Status: published on GitHub, TestPyPI and PyPI. Final read-only verification
passed all seven jobs; the initial production Linux 3.11 install lookup failed
before application checks and remains failed historical evidence. Tracked by
[issue #326](https://github.com/krivonosoff161/agentic-security-harness/issues/326),
delivered by [PR #327](https://github.com/krivonosoff161/agentic-security-harness/pull/327).

The additive [controlled file workflow](../controlled-file-workflow.md) makes
bounded actual writes to newly created public-synthetic fixtures. Quarantine,
retained ancestry and report-only public Runtime Guard remain separate gates.
The read-only verifier compares disk bytes and recomputes captured commitments.
Guarded/ablated deterministic controls are separate from fresh model observations.

[Fresh installed-candidate observation](../controlled-file-observation-20261001.md):
eight real local-model calls, four protected proposals denied, four report writes,
two correct reports; independent disk/history verification passed. The fixed causal
control changed protected bytes only with Guard deliberately ablated. The initial
zero-call startup failure and two resource deferrals remain recorded. The candidate
wheel is separately identified, not relabelled as the final release subject.

## Limits

This feature does not confer arbitrary filesystem, shell or code-execution access.
It assumes a trusted broker and caller. Hostile native code, uncaptured events,
coordinated history rollback, remote origin authentication and ambiguous external
effect recovery remain outside this bounded result. Existing issues #314/#316/#317/#318
are not closed by adding this reproducible benchmark path.
