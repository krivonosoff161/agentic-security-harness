# Agentic Security Harness v1.14.1

Status: published on PyPI and TestPyPI, with successful seven-job read-only
cross-index verification. The initial production workflow remains failed
overall at a Linux 3.12 index lookup. The prior published
[1.14.0 release](v1.14.0.md) retains its original subjects and evidence. This
patch resolves the optional-framework migration behind superseded proposal #342.

Locations: [GitHub Release](https://github.com/krivonosoff161/agentic-security-harness/releases/tag/v1.14.1),
[PyPI](https://pypi.org/project/agentic-security-harness/1.14.1/), and
[TestPyPI](https://test.pypi.org/project/agentic-security-harness/1.14.1/).

## Scope

- Move the optional `document-agent` extra, framework admission, examples and
  evidence checks to exact `pydantic-ai-slim==2.54.0`, with matching
  `pydantic-graph==2.54.0` and `genai-prices==0.1.9` in both hash-locked
  verification environments. The base package still does not import or require
  the optional framework.
- Preserve one host-bound tool, no native/output tools, disabled automatic
  instrumentation, bounded requests, single generator invocation and refusal
  after an ambiguous effect. Unsupported framework versions refuse before
  optional import in the direct factories.
- Keep the cold offline checker usable on Windows without allowing a shell
  command: stdlib version probes are denied and fall back to native platform
  data, then third-party import and dispatch run under strict process/network
  denial. Denied bootstrap probes are reported separately.
- Refresh the eight-case deterministic boundary seed from the matching actual
  framework run. Historical model observations and published 1.14.0 subjects
  are unchanged; this patch adds no new model study, connector or authority.

## Boundaries

The factories do not sandbox a caller-provided model or generator. An explicit
instrumented model can retain caller-configured telemetry; a generator can use
a transport. The local bridge uses its own uninstrumented FunctionModel, and
the no-provider offline checker is separately audited. Neither mechanism makes
document content trustworthy, grants a new path permission, or proves general
model-task correctness. Independent human-review issues #199/#205 remain open.
Delivery is tracked in #357; Scorecard governance alert #17 remains unresolved.
