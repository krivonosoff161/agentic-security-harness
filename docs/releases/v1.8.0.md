## Release scope

The opt-in [retained ancestry store](../ancestry-store.md) keeps exact captured
bytes, identifiers, context, admitted parents and narrowing scopes. Callers create
the trusted root explicitly. A separate checkpoint witness and cross-process lock
bind reads and append/recovery transitions. Missing, rebound, cyclic or stale
candidate histories stop before component evaluation. Valid ancestry does not
override a Gateway denial and never creates operational authority.

This is an additive 1.x API, so the release is 1.8.0 rather than a 1.7.x bug-fix patch.
Companion package versions and their source ownership are unchanged.

## Evidence limits and remaining research

Trusted capture, admitted initial root and access-controlled store/witness paths
are prerequisites. A second filename is not an independent hardware trust anchor.
Coordinated rollback of database and witness, unauthenticated remote origin,
uncaptured host events, power-loss durability and external exactly-once effects
are not established. Event completeness and broader recovery remain separately
tracked in issues [#316](https://github.com/krivonosoff161/agentic-security-harness/issues/316)
and [#317](https://github.com/krivonosoff161/agentic-security-harness/issues/317).

Prior local-model observations and full private derivations remain separate from
public release checks. This release makes no new model-success, general-safety,
production-effectiveness or independent human-review claim.
