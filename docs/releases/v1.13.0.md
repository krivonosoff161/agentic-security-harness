## Additive scope

- Document generation passes content to the host-bound `document` text tool.
  The host fixes the alias, policy and create-only destination before the model
  runs. The existing lower-level `GuardedWorkspace` proposal API and Guard
  remain available.
- A review-required prior document needs an exact-byte host review digest
  before it can be reused as untrusted data. Failed declared quality cannot
  be overridden by that digest. Exact-JSON generation requests syntax only;
  expected answers remain in the host-side evaluator.
- Opt-in source restrictions bind input bytes, class, forwarding/storage
  permissions and original expiry. Bounded multi-source composition retains
  each original leaf and uses restrictive joint admission through later jobs.
- Fixed host plans, `document-plan`, and read-only `document-coverage` bind
  expected task/input/restrictions/output checks. Dynamic
  `document-admissions` records pending decisions and later job-or-stop choices
  under a separately retained head; sealing closes declared history, not
  document correctness or all host actions.
- Optional supervised execution owns one child. After a validated closure or
  owned-child fence, exact existing bytes may be reviewed as data for a
  **new** job. The interrupted ID is spent; neither its effect nor its
  completion is replayed or inferred.

The [operator guide](../document-workflow.md) and
[clean-install replay protocol](../document-workflow-replay.md) describe the
host inputs, scripted acceptance and human review boundary. No new base
dependency, arbitrary-path write tool, automatic retry, semantic classifier,
or OS sandbox is introduced.
The version-bound distribution description is `PACKAGE_README.md`; its source
version is not evidence that a package index has published these bytes.
