## Scope

This additive minor candidate for [issue #338](https://github.com/krivonosoff161/agentic-security-harness/issues/338)
wraps the existing create-only
[GuardedWorkspace](../guarded-workspace-writer.md) with a usable
[document workflow](../document-workflow.md): host-owned configuration and
local-model choice, no-effect preview, one explicit generation per exclusive
job ID, read-only status, and an optional separately pinned Pydantic AI bridge.
A second job can consume a verified earlier document under the same configuration,
but that text is untrusted input, never an action or policy grant. The host
owns output aliases, paths, classification, task and any requirements.

Host-declared exact JSON and bounded Markdown checklist checks yield
content-free `failed`, `review_required` or `checked` status. Invalid-format
output remains a saved draft, causes CLI exit 2 and is not chainable. A result
marked `checked` met only declared deterministic criteria; it is not a claim
of factual truth or independent human review. No OS sandbox, arbitrary path
writer, semantic labeler, network provider permission or retry mechanism is
added. The [v1.11.0](v1.11.0.md) subjects and release evidence remain immutable.
This delivery contributes evidence toward the separate research question #318;
it does not close that issue or prove semantic document quality.
