# Agentic Security Harness v1.4.0

This document describes the release source for Agentic Security Harness v1.4.0. The
document alone is not a tag, GitHub Release, TestPyPI/PyPI publication, deployment, or
production-enforcement claim; those states require their exact external evidence.

## Highlights

- Five public companion module groups are expressed as exact passive package extras:
  `transfer`, `handoff`, `playbooks`, `router`, and `filter`.
- The `all` extra is the exact union of those groups and contains no Git URL, local path,
  editable dependency, generic `llm-router` coordinate, or private Runtime Guard package.
- Every companion coordinate was independently built, attested, promoted through
  TestPyPI, clean-installed, published to PyPI, and clean-installed again before this
  release source was finalized.
- Clean production-PyPI resolver tests cover each group and the complete union in fresh
  environments without a pre-existing wheelhouse.

## Installation and authority boundary

After public index availability for `1.4.0` is confirmed, examples include:

```bash
python -m pip install "agentic-security-harness[router]==1.4.0"
python -m pip install "agentic-security-harness[all]==1.4.0"
```

Installation is passive. It grants no discovery, import, loading, binding, provider
access, execution authority, deployment, enforcement, approval, or certification.
Runtime Guard remains private and `contract_only` and is not part of any public extra.

## Evidence and limitations

The release gate reruns the complete test, Ruff, mypy, artifact-validation, reproducible
wheel/sdist, installed-package, SBOM, checksum, and attestation contours. TestPyPI and
PyPI promotion must bind the exact tag build, exact hashes, and clean installed-wheel
validation before publication can be reported as complete.

The deterministic and synthetic Harness results remain reproducibility evidence, not a
production safety certification. Independent standards validation and independent
maintainer review remain unclaimed.
