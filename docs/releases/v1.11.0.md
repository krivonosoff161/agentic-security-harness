## Scope

This additive release introduces the
[guarded workspace writer](../guarded-workspace-writer.md) for actual UTF-8
document creation. A trusted host configures an existing output directory,
named aliases, filenames, byte limits and a declared data class. Untrusted
proposal bytes supply only `operation=write_text`, an alias and content. Strict
parsing and deterministic Runtime Guard precede exclusive creation of the
configured new file. Readback and content-free intent/result receipts permit
subsequent local verification. Existing destinations are never overwritten.

The Python `WorkspacePolicy` / `GuardedWorkspace` API and installed
`workspace-check`, `workspace-write`, `workspace-verify` commands support an
existing application agent loop and offline proposals. `workspace-run` offers
one explicit local Ollama request only with `--execute`; no new model or base
dependency is installed. A host must trust its process, policy, directory and
operating system and restrict any other tools offered to the agent. This is not
an OS sandbox, arbitrary-path writer, semantic classification of content,
remote authentication or a multi-file transaction.

The 1.10.1 `ControlledFileSession` and its fixed-fixture observations remain
separate. No new real-model observation was made for the workspace writer.
